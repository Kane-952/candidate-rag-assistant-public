# 手动更新展示仓库

展示仓库维护虚构资料、配置模板和通用资源，采用独立 Git 历史。

## 更新流程

1. 在本地工作目录导出选定源 commit 的跟踪文件。
2. 替换知识库、前端身份与 SEO、头像、LLM 提示、邮件模板、关联测试、文档和评测数据。
3. 检查教育、雇主和项目组合，确保展示资料完整脱敏。样例邮箱使用 `example.com`。
4. 审查候选文件及差异，扫描身份、联系方式、路径、凭据和资源元数据。
5. 运行回归测试，在展示仓库提交并记录来源 commit 与修改范围。

## 文件与提交规则

更新文件保留源码、虚构样例、配置模板和说明。`.env`、数据库、索引、收件箱、日志、缓存和导出结果保存在私有运行目录；源仓库历史和私有审查材料留在原工作目录。

使用公开账号称呼与 GitHub noreply 作者邮箱，在展示仓库独立提交。每次更新重复文件审查、扫描和测试。

## 凭据处理

发现真实凭据进入可访问历史时，先轮换凭据，再清理相关文件与历史。
