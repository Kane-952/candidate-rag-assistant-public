# 延迟与请求调度

应用启动时预热 Embedding 和可选重排模型。模型或索引初始化失败时，健康检查返回 unavailable。

`MAX_PENDING_CHATS=4` 定义执行中与等待中的请求总上限，满额返回 429。全局锁串行执行本地推理，事件队列容量为 2，服务使用单 worker。

流式连接断开后取消等待和后续阶段。已发出的模型请求在响应或 HTTP 超时后退出；本地同步推理完成当前阶段后检查取消状态。

运行 `python scripts/benchmark_latency.py`，通过配置的服务地址与本地鉴权执行四次问答，记录：

- `first_visible_ms`：请求开始到核验后首段正文到达的时间。
- `total_ms`：请求开始到响应流结束的时间。
- 管理员 Trace：模型加载、检索、重排、生成和核验各阶段耗时。

该脚本调用配置的模型 API。具体运行数据保存到本地；性能评测计划见 README 的“局限性与后续改进”。
